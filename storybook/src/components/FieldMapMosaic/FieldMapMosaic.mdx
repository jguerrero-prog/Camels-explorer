# FieldMapMosaic

A grid of 2D field maps, one cell per realization, for comparing at a glance.

`Source: code`

## Anatomy

```
.field-map-mosaic            grid, 4px gaps, min-height 340
└── .field-map-mosaic__cell    radius 6, surface/control, 1px border/subtle
    ├── __image                object-fit: contain
    ├── __realization-tag      top left, black at 55%, Lato Bold 10
    └── __no-data              for a cell with no map
```

A missing cell keeps its place and takes `surface/content` instead of `surface/control`, so a gap in the
sequence is visible rather than silently reflowing the grid.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-surface-control` | Cell background |
| `--color-surface-content` | Empty cell background |
| `--color-border-subtle` | Cell border |
| `--color-text-muted` | The no-data message |
| `--neutral-white` | Realization tag text, over a black scrim |

The tag is the one place a primitive is referenced directly, because it sits on a translucent black scrim
rather than on any themed surface.

## Behaviour

- `rows` and `cols` come from `FieldMapGroupControl`. The component does not choose its own extent.
- Cells are filled with consecutive realizations starting from the tile's current one.
- Images use `object-fit: contain`, so a non-square map is letterboxed rather than distorted.

## Accessibility

- `Source: gap`. Cell images have no `alt`, so the realization tag is the only identification and it is
  visual only. Each cell should name its field and realization.

## Content

The tag is the realization label exactly as it appears elsewhere: `LH 42`, not `Realization 42`.

## Use it

- Comparing the same field across consecutive realizations in one tile.

## Don't use it

- For one map. Render the single map.
- For different fields side by side. That is several tiles.
