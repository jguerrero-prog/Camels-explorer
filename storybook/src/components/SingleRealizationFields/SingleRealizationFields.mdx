# Realization fields (single)

The same opening block as `Realization fields`, for statistics that can only show one simulation at a time.
No compare mode, no multi-select.

`Source: code`

## Anatomy

```
Suite            SelectField
Set              SelectField
  1P             SelectField "1P Parameter" + OptionSlider "Variation"
  otherwise      NumberStepper "Realization"
```

## Variants and states

Two options change the shape of the block:

- **`hideRealizationValueControls`** drops the variation slider and the realization stepper, for statistics
  where the suite and set alone identify the output.
- **`onepScheme`** selects how a 1P run is identified. `modern` uses `1P_p{index}_{variation}`; `legacy`
  uses `1P_{index}_{variation}` with six parameters and no `p`. Which scheme a statistic uses depends on how
  its files were written, so it is a per-statistic setting rather than a global one.

`allowedSetsForSuite` narrows the set list per suite, for statistics whose coverage differs between suites.

## Tokens

None directly. Every visible surface belongs to the fields this block composes.

## Behaviour

- Changing the set resets the realization, and picks the correct 1P identifier form for the active scheme.
- Legacy 1P parameter names come from the catalog where they are published, and fall back to `p1`, `p2`.

## Accessibility

Inherited from the composed fields.

## Content

Identical conventions to `Realization fields`: set labels rather than codes, published parameter names
where they exist, numbered fallbacks where they do not.

## Use it

- For a statistic that renders one simulation per tile, such as a profile or a map.

## Don't use it

- Where overlaying several realizations is meaningful. Use `Realization fields`.
