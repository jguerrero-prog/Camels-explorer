# CopyAsCodePopover

Shows the Python that reproduces the plot on screen, ready to copy into a notebook.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-surface-popover` | Popover fill |
| `--color-surface-content` | Code block ground, pointer |
| `--color-border-subtle` | Border, pointer edges |
| `--color-text-primary` / `--color-text-emphasis` / `--color-text-muted` | Code, title, controls |
| `--color-syntax-keyword` / `--color-syntax-string` / `--color-syntax-number` / `--color-syntax-comment` | Highlighting |
| `--color-success` | The "Copied" confirmation |
| `--font-mono` | Code block |
| `--font-label` | Title |

The four syntax tokens exist for this component alone, which is why they are worth knowing about: any other
code surface should use them rather than inventing colours.

## Behaviour

- Highlighting is done by `lib/highlightPython`, a small tokenizer, not a syntax library. It emits keyword,
  string, number and comment spans and leaves everything else unstyled.
- Copy writes to the clipboard and shows the confirmation for 1.5 seconds.
- The code is displayed, not editable. Editing it here would not change the plot.

## Accessibility

- Both controls carry `aria-label` and `title`, and the pointer is `aria-hidden`.
- `Source: gap`. The popover has no role and no label of its own, no focus management and no Escape, and
  "Copied" is visual only, with no live region to announce it.

## Content

The snippet is real, runnable Python against the CAMELS data paths. This is the one place in the interface
where code is the content, so it is never truncated or elided.

## Use it

- Moving from exploring in the browser to working in a notebook.
- Recording exactly how a figure was produced.

## Don't use it

- As a general export. Use the download actions for data or images.
