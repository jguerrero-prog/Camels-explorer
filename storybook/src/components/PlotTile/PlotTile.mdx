# PlotTile

The populated (has-a-plot) tile, from Figma node `1019:10`. `Tile.mdx` explicitly flagged this as a separate, not-yet-designed variant rather than something to bolt onto `Tile` via a prop — this is that variant, built as its own component sharing `Tile.css`'s `.tile` card shell (background/border/radius/shadow/padding) rather than duplicating it.

## Token

Inherits `.tile`'s tokens from `Tile.mdx` (`--color-surface-content`, `--color-border`, `--font-ui`) unmodified — see Spec below for why `PlotTile` doesn't add its own.

Composed children carry their own tokens — see `PlotChart.mdx`, `StaticImageChart.mdx`, `ParamsReadout.mdx`, `UnderlyingHalos.mdx`.

## Spec

- Title row (reuses `.tile__title`), then a body row (chart + `ParamsReadout` side by side), then `UnderlyingHalos` as the last child (when present) — matches the frame's vertical stacking exactly.
- `chart.kind` (added 2026-08-05, default `'plotly'` when omitted): `'plotly'` renders `PlotChart` (Static/Interactive toggle, when `imageUrl` is given); `'static-image'` renders `StaticImageChart` instead (real PNG only, no toggle) — for statistics with no Plotly equivalent at all. See `StaticImageChart.mdx`.

<Canvas of={PlotTileStories.StaticImageOnly} />

- Clicking anywhere on the tile calls `onFocus` — real wiring, not decorative: `App.tsx` uses this to swap the left 280px slot to this tile's own `ParamsSidebar` (see Usecase). Which tile is focused lives entirely in `App.tsx`'s own `focusedTileId` state — `PlotTile` has no `focused` prop of its own to reflect it.

**Corrected 2026-08-04: removed a `focused` prop and its visual border entirely, not just the styling.** An earlier pass took a `focused` prop and drew a thin `--color-accent-gradient-start` border with it — both removed on direct user feedback that the border was an unrequested addition, not sourced from any frame. `onFocus` alone is enough: `PlotTile` doesn't need to know whether it's currently focused, only to report clicks.

<Canvas of={PlotTileStories.CompareMode} />

**Real, deliberate scope decision — why this isn't just `Tile` with a prop:** `Tile.mdx`'s own "Usecase" section already ruled this out ("that's a different enough anatomy... deserves its own documented variant"). The populated anatomy (chart + readout + collapsible halos table) shares nothing structurally with the empty state's single centered button, so a shared prop would mean two unrelated render branches inside one component — a separate component sharing only the outer card CSS is the honest shape.

## Usecase

- Real usage: `App.tsx`'s canvas, replacing the empty-state `Tile` once the Add Plot modal's Curated tab submits one of the statistics with real end-to-end chart wiring built so far — **Stellar Mass Function, Halo Mass Function, Baryon Fraction, Power Spectrum, Bispectrum, SFR History** (the six statistics sharing `backend.py`'s `_render_result_png` path — see `MassRangeSidebar.mdx`/`PowerSpectrumSidebar.mdx`/`BispectrumSidebar.mdx`/`SFRHistorySidebar.mdx`). Submitting any other statistic still adds the old title-only empty `Tile` — a real, honest gap, not silently papered over with fake chart data for statistics that aren't wired yet.
- `onFocus` is real, wired state in `App.tsx`: clicking sets `focusedTileId`, and the focused tile's own real sidebar composition then lives in the left 280px slot (same slot `IconRail`'s Project/Files panels use — mutually exclusive, per `STUDIO_PLAN.md`); editing those fields refetches this tile's chart.
- Compare mode (`chart.series.length > 1`), where supported, is driven by the sidebar's "Realizations to compare" `MultiSelect` — one fetch per selected realization, same suite/set/params, overlaid; `chart.imageUrl` gains one `realizations=` query param per selection the same way. Bispectrum supports this for free via the same generic path; Power Spectrum/SFR History do too.
- **`halos` is `null` for Power Spectrum, Bispectrum, and SFR History** (real 2026-08-05 addition) — these are field/box-level statistics with no per-halo catalog concept at all, unlike the three mass-range statistics whose `halos.rows`/`halos.rawRows` come from the same real `GET /api/halo-catalog` fetch. `halos.massContextNote` (only set for Halo Mass Function/Baryon Fraction) is unrelated to this — see `UnderlyingHalos.mdx`'s 2026-08-05 note on why their plotted quantity has no matching column in the per-subhalo catalog shown below the chart.

## Code

```tsx
import { PlotTile } from '@/components/PlotTile/PlotTile';
import { massRangeImageUrl } from '@/lib/api';
import { MASS_RANGE_CONFIGS } from '@/components/MassRangeSidebar/massRangeConfig';

function MassRangeTile({ statistic, result, params, catalog, onFocus }) {
  const config = MASS_RANGE_CONFIGS[statistic];
  return (
    <PlotTile
      title={statistic}
      chart={{
        series: [{ label: `${params.setName}_${params.realizations[0]}`, x: result.x, y: result.y }],
        xLabel: result.x_label,
        yLabel: result.y_label,
        logX: result.log_x,
        logY: result.log_y,
        imageUrl: massRangeImageUrl(config, params),
      }}
      readoutGroups={[
        { label: 'Suite / Set', value: `${params.suite} · ${params.setName}` },
        { label: 'Realizations (compare)', value: params.realizations.join(', ') },
        { label: config.rangeLabel, value: `${params.min.toExponential()} – ${params.max.toExponential()}` },
        { label: 'Bins', value: String(params.bins) },
      ]}
      halos={{ rows: catalog.frame, rawRows: catalog.raw_frame }}
      onFocus={onFocus}
    />
  );
}

// Power Spectrum/Bispectrum/SFR History: same PlotTile, halos: null.
function NoCatalogTile({ statistic, result, params, onFocus }) {
  return (
    <PlotTile
      title={statistic}
      chart={{ series: [{ label: '...', x: result.x, y: result.y }], xLabel: result.x_label, yLabel: result.y_label }}
      readoutGroups={[{ label: 'Suite / Set', value: `${params.suite} · ${params.setName}` }]}
      halos={null}
      onFocus={onFocus}
    />
  );
}
```
