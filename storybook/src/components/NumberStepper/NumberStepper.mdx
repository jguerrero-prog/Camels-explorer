# NumberStepper

A numeric field with increment/decrement buttons. Real source: Figma node `1055:56` ("field-z max"). Partially resolves the "Stepper" gap flagged in `STORYBOOK_STRUCTURE.md`'s initial inventory — **but that flag meant a multi-step wizard progress indicator, a different thing with the same common name.** This component is the numeric-value kind; the wizard kind remains undesigned.

## Token

- `--color-surface-control` / `--color-border-subtle` — the input row, same as `SelectField`'s
- `--color-surface-chrome` — the two increment/decrement buttons' own background (matches TopNav/IconRail's chrome tone, not the control surface)
- `--font-label` (Lato) — label
- `--font-ui` (Inter) — value

- Optional `caption` line below (11px muted), same pattern as `SelectField`'s.

**Corrected 2026-08-04 — real bug fixed, not a Figma correction:** the value used to be a plain, non-interactive `<span>` — only the +/- buttons could change it. Caught when this component was needed for the Add Plot modal's Realization field and the user pointed out steppers "are meant to be flexible where I can type a number as well." Now a real editable `<input>`: typing commits on blur or Enter, Escape reverts to the last committed value, and invalid/empty text reverts too rather than silently accepting garbage. The +/- buttons and typing are equally valid, real ways to set the value.

**Fixed 2026-08-08 — real bug found in direct QA, a second one after the fix above:** every real caller wires `onChange` straight to a backend refetch (e.g. Realization inside `SingleRealizationFields`/`RealizationFields`, used by 18+ sidebars) — the +/- buttons used to call `onChange` synchronously on every click, so clicking 5 times in a row (say, Realization 4→9) fired 5 separate loads instead of one, confirmed via repeated 404s in the console for each intermediate value. Now debounced 300ms after the last click, same `Slider`-precedented fix as its own `COMMIT_DEBOUNCE_MS` (see that component's docs) — the displayed number still updates instantly per click for responsiveness, only the actual `onChange`/refetch waits for a pause. Typing + blur/Enter was never affected (already committed once, immediately) and needed no change.

## Usecase

- Real usage: SFR History's "z max" field — but this, and the redshift-range field it may or may not replace, are explicit placeholders (confirmed 2026-08-04, see `ParamsSidebar.mdx`). Which control z_min/z_max actually end up using is intentionally undecided until real data wiring informs the choice — don't treat this component as the final answer for that field.
- Real usage: the Add Plot modal's Curated tab "Realization" field (see `AddPlotModal.mdx`) — the first place this component's typing behavior is actually exercised, not just its buttons.
- Reach for this over `Slider` when the value has no natural visual range to scrub (or the step size matters more than the position within a range).

## Code

```tsx
import { useState } from 'react';
import { NumberStepper } from '@/components/NumberStepper/NumberStepper';

function ZMaxField() {
  const [value, setValue] = useState(10.0);
  return (
    <NumberStepper
      label="z max"
      value={value}
      step={0.1}
      onChange={setValue}
      formatValue={(v) => v.toFixed(1)}
    />
  );
}

function RealizationField() {
  const [value, setValue] = useState(0);
  return (
    <NumberStepper
      label="Realization"
      value={value}
      onChange={setValue}
      caption="0–999"
    />
  );
}
```
