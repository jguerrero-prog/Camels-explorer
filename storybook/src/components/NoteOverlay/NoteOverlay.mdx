# NoteOverlay

A draggable card on a tile, for a remark that is not tied to a data point. Built to survive a screenshot
into a slide.

`Source: code`

## Anatomy

```
.note-card                   200px, z-index 6, positioned by percentage
├── __handle                 drag area, holds __delete
├── __text                   click to edit
└── editing: __input (textarea, autofocused) + __save
.note-card--dragging         while a drag is in progress
```

## Variants and states

<Canvas of={Stories.OnWhiteChartCard} />

The white-card story is the reason the card is opaque. A note sits over dark chrome in one place and a white
plot in another, and a translucent fill takes its contrast from whatever happens to be behind it. The card
is a solid crimson with white text, so it reads the same in both positions. See Decision log, DR-003.

Three states: at rest, editing (click the text), and dragging.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-note-surface` | Card fill |
| `--color-note-border` | Card border |
| `--color-note-text` | Text, and the Save button fill |
| `--font-label` | Save button |

No drop shadow, matching the annotation callout: the card sits on the page rather than above it.

## Behaviour

- Dragged by its handle. The drag is measured against the enclosing `.plot-tile__chart-area`, so a note
  stays inside the chart region and is stored as a fraction of it.
- Position is clamped to 0–1, so a note cannot be dragged out of its tile.
- Move events are bound to the window during a drag and removed on release, so a drag continues even when
  the pointer leaves the card.
- Clicking the text opens an editor; Save trims and commits. Clicks are stopped at the card.
- `hidden` on a note is honoured by the Hide popover's Notes category, not here.

## Accessibility

- The delete control carries `aria-label` and `title`, and `:focus-within` reveals it rather than hover
  alone, so a keyboard user can reach it once focus is in the card. The same pattern hides it from a
  screenshot.
- `Source: gap`. Dragging is pointer-only, with no keyboard way to move a note; the card itself is not
  focusable; and the text is made editable by a click handler on a paragraph rather than by a control.

## Content

The note is the user's own words. Nothing here is supplied by the interface.

## Use it

- A remark about the figure as a whole.
- A caption that needs to survive into a slide or a paper.

## Don't use it

- For a comment about one point in the data. Use `AnnotationOverlay`.
