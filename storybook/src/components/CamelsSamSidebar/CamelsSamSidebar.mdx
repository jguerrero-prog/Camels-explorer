# CamelsSamSidebar

CAMELS-SAM's real per-tile sidebar, wired 2026-08-07 (direct user request) from `app.py`'s own "CAMELS-SAM" tab; Set control added 2026-08-08 (issue #24). Deliberately not built from `SingleRealizationFields` — this statistic has no Suite concept at all (`backend.py`'s `get_sam_catalog` has no suite parameter, since the Santa Cruz Semi-Analytic Model runs on N-body-only sims, a wholly separate dataset from the 4 hydro suites). Set is a plain `Radio` instead — `backend.py`'s `PUBLIC_SAM_SETS = {"LH", "CV"}` has only 2 real options (1P stays unsupported — a real 403 on a plain fetch, not yet resolved).

## Token

Composed from `Radio`/`NumberStepper`/`Button` — no tokens of its own.

## Spec

- **Set (LH/CV)** — real, `backend.py`'s `PUBLIC_SAM_SETS`. CV's real per-realization folder name (`fid-sc-sam`) and count (5, not 1000 — CV_5 confirmed empty) differ from LH's, both resolved server-side.
- **Realization**, bound clamped to the selected set's real count (`SAM_SET_REALIZATIONS`) — matches `app.py`'s own `st.slider("SAM realization (LH)", 0, 999, 0)` for LH; CV's real range is 0–4.
- **Real, deliberate simplification vs. `app.py`**: Streamlit's tab also has a "Minimum stellar mass" slider and a "Show all available fields (raw)" checkbox in the tab body itself, filtering *both* the table *and* the two charts below it. Here, that same real filter/raw-toggle lives inside `UnderlyingHalos`'s own `filter`/`rawRows` props (via `PlotTile`'s "Table" mode) instead of this sidebar — consistent with every other statistic in this app, where the table's own mass filter is independent of the chart above it (Stellar Mass Function's histogram doesn't shrink when its table's mass slider moves, either). The charts always show every real galaxy in the realization; only the table is ever filtered.

## Usecase

- Real usage: `App.tsx`'s canvas — `onChange` triggers a real refetch of `GET /api/sam-catalog`.
- **Real-data only, no synthetic fallback** — `get_sam_catalog()` returns `None` outright when unavailable, same reasoning as `get_halo_catalog()` (a fabricated SAM catalog isn't a useful stand-in the way a fabricated curve is).
- The tile's own chart area shows two real panels side by side (matching `app.py`'s `st.columns(2)`) — a log-log Stellar Mass vs. Halo Mass scatter and a real 3D `Plotly3DChart` of galaxy positions colored by log₁₀ stellar mass. See `App.tsx`'s `loadCamelsSamTile`.
- The "Table" `ChartModeDropdown` option (`PlotTile`'s `halos` prop) shows the same real per-galaxy GALPROP catalog `UnderlyingHalos` already renders for every other statistic — Stellar/Halo/BH/Cold Gas Mass, SFR, position, with the real 41-column raw escape hatch.
- **Full realization, loaded progressively (2026-08-07, direct user request: "wire in all 47/8... use lazy loading... so we don't slow down the site").** Each LH realization is split across 8 real spatial octants (`SAM_OCTANTS`); `loadCamelsSamTile` fetches octant `0_0_0` first for a fast initial render, then `streamRemainingSamOctants` fetches the other 7 in the background (4 concurrent requests, batched every 2 octants) and appends their galaxies as they land. The tile's "Octants loaded" readout tracks progress (e.g. `3/8`) instead of blocking the UI until the whole realization has arrived. This replaces the earlier single-octant (1/8-volume) sample — same pattern applied to Initial Conditions' 47 files, see `ICParticlesSidebar.mdx`.

## Code

```tsx
import { useState } from 'react';
import { CamelsSamSidebar } from '@/components/CamelsSamSidebar/CamelsSamSidebar';
import type { CamelsSamParams } from '@/components/CamelsSamSidebar/CamelsSamSidebar';

function FocusedTileSidebar() {
  const [params, setParams] = useState<CamelsSamParams>({ setName: 'LH', realization: 0 });
  return (
    <CamelsSamSidebar
      params={params}
      onChange={setParams}
      onRemove={() => {/* remove this tile from the canvas */}}
    />
  );
}
```
