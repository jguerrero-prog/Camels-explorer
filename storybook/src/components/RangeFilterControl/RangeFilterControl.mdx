# RangeFilterControl

Two bounds on one field: typeable min and max boxes above a dual-thumb track.

`Source: code`

## Anatomy

```
.range-filter
├── .range-filter__label     Lato Regular 12
├── .range-filter__inputs
│   ├── .range-filter__number   min, typeable, Inter Semi Bold 12
│   ├── .range-filter__dash

└── .range-filter__track-wrap
    ├── .range-filter__track / __fill   the selected span in the accent gradient
    └── .range-filter__thumb x2         one per bound
```

## Variants and states

CAMELS fields span from `params_*` values around 0 to 1 up to `Group_M_Crit200` at 1e10 to 1e15. The default
formatter switches to exponential outside the range 1e-3 to 1e5, because `toFixed(3)` on a halo mass
overflows a sidebar-width input.

## Behaviour

- Two native range inputs stacked over one visible track, so both thumbs are keyboard reachable.
- Number spinners are suppressed. A default spinner step is meaningless across fifteen orders of magnitude,
  and FlatHUB's own inputs are plain typeable boxes.
- `min` and `max` are the field's live bounds. The caller must not render this control until it has real
  bounds; there is no placeholder range.
- `step` defaults to 500 steps across the supplied range.

## Accessibility

- Both thumbs are native range inputs, so arrows, Home and End work.
- `Source: gap`. Neither input has an `aria-label`, so a screen reader cannot tell the two thumbs apart.
  They need "minimum" and "maximum" names.
- Nothing prevents the thumbs crossing by keyboard.

## Content

Label is the field name exactly as the catalog spells it, including underscores: `Group_M_Crit200`. Units in
square brackets when the catalog provides them.

## Use it

- One per catalog field added from the filter tree, in the Custom plot pattern.

## Don't use it

- For a single bounded value. Use `Slider`.
- For a field with no live range. Show the "no range available" state instead.
