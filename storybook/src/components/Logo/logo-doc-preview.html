Brand / Logo

Shown here on a dark ground deliberately — this is also the unresolved contrast check flagged in Spec below. Source: Figma "Denario" file, node 1106:1364, frame "Logo specs."

The CAMELS brand mark: a camel silhouette filled with a cosmic-nebula texture and overlaid physics/astronomy notation, paired with a "CAMELS" wordmark rendered in the same texture. Documented in the mandated order for every entry in this system — Token, then Spec, then Usecase, then Code — so every visual decision traces back to a reusable value, a defined contract, a reason to use it, and a real snippet, in that order.

01

Token

The logo's gradient is not built from live tokens — it's a flattened raster image (see Spec). What is a real, reusable token set is the brand color palette baked into that gradient: 12 named swatches, extracted directly from the Figma frame's own layer names and fills — nothing invented, nothing added on top.

02

Spec

VariantAssetReal dimensionsBackground
Icon (camel mark only)camels-icon.png1112 × 1030 pxtransparent
Wordmark ("CAMELS" text only)camels-wordmark.png~1456 × 336 pxwhite

There is currently no combined icon+wordmark lockup as its own exported asset — the source Figma frame places them separately (icon at x:210,y:802, wordmark at x:165,y:330), not as one grouped component. The hero above composes them live with a flex gap; that is not the same as a real, exported lockup asset.

No vector (SVG) version Both variants are flattened raster exports. No crisp small-size rendering — a favicon or app icon at 16–32px will render the nebula texture as noise, not a clean mark — and no way to recolor programmatically.
No monochrome / single-color variant Every current use is the full 12-color cosmic gradient. There is no reversed (light-on-dark) or flat single-tone version — a real risk for the planned High-Contrast Dark theme, not a hypothetical one.
Dark-theme contrast is unverified The wordmark's background is opaque white; the icon is transparent but was only ever checked against a light canvas in Figma. Confirm visually against the real --color-surface token in System Dark and High-Contrast Dark before shipping either into a dark nav — don't assume.
Unoptimized production originals camels-icon.png is 1.1MB, camels-wordmark.png is 350KB — fine for this documentation pass, but each real use (favicon, nav bar, splash) needs its own appropriately sized, compressed export, not one oversized PNG scaled down in CSS.
03

Usecase

Established
Icon alone
Favicon, app/window icon (the desktop.py pywebview window), loading/splash state — anywhere too tight for the wordmark. Blocked below ~64px until the no-SVG gap is closed.
Established
Wordmark alone
Top nav / header branding, About screen — anywhere the product name needs to read clearly without the icon's illustrative detail competing for attention.
Needs the lockup gap closed
Icon + wordmark together
Splash screen, About/credits, marketing-style contexts. Needs a real composed (and exported) lockup first — not assumed to already exist.
Recommendation, not decided
Palette as data-viz scale
A candidate categorical color scale for Studio's Compare/overlay mode and cross-finder comparisons — a stable, distinguishable, on-brand color per suite/finder/tile. Flagged here so it's considered deliberately, not invented ad hoc inside a future chart component.

components/Logo/Logo.tsx
import wordmark from './assets/camels-wordmark.png';
import icon from './assets/camels-icon.png';

type LogoProps = {
  variant: 'icon' | 'wordmark';
  height?: number;
};

export function Logo({ variant, height = 32 }: LogoProps) {
  const src = variant === 'icon' ? icon : wordmark;
  return <img className="logo" src={src} alt="CAMELS" style={{ height }} />;
}
