# Toolbar

The tool row that sits in the header between the folder/project name and "Add Plot" — real across all three frames it appears in (Figma nodes `1078:30`, `1068:48`, `1046:40`), identical every time, so this is a stable, confirmed component, not a one-off mock.

## Token

- `--color-border-subtle` — the divider between the tool group and the AI agent icon, and the active-tool background tint
- `--color-surface-toggle` / `--color-surface-toggle-active` — the grid/stacked view-mode toggle's own background and its selected option

## Spec

Left to right: **Annotate → Ratio/diff → Ruler → Linked brushing → Copy provenance → Copy as code** (six 36×36 tools, 18×18 icons, 8px radius) → a 1px divider → **AI agent** → an 8px spacer → a grid/stacked **view-mode toggle** (32×32 options inside a padded, rounded container). Every real name matches a toolbar candidate already listed in `STUDIO_PLAN.md`'s "Adding tiles" section almost exactly — this frame is that list, built.

**This is skeleton-level, not a working toolbar:**
- Every tool prop (`onAnnotate`, `onRatioDiff`, etc.) is optional and does nothing by default — none of these seven tools have real behavior wired yet. This component is the real, named slots, not the features themselves.
- Only `viewMode`/`onViewModeChange` are functional — the one piece this pass actually needed, since it drives `Viewer`.
- The real `tool-ratio-diff` icon in Figma has small chevron overlays baked into its own SVG (no separate button chrome around it, unlike its five siblings). This component simplifies it to the same plain icon-button treatment as the others — a deliberate skeleton-level simplification, not a missed detail.

## Usecase

- **Resolved 2026-08-05:** lives inside `TopNav`'s header row via its real `toolbar` prop (see `TopNav.mdx`) — `App.tsx` originally rendered this as a second row beneath `TopNav`, a real layout bug fixed once the real merged-header frame (Figma node `1012:1124`) confirmed it belongs in the same row.
- `viewMode` should be lifted to whatever owns `Viewer` (see `Viewer.mdx`) — this component doesn't own view-mode state itself, it just displays/toggles it.

## Code

```tsx
import { useState } from 'react';
import { Toolbar } from '@/components/Toolbar/Toolbar';
import type { ViewMode } from '@/components/Toolbar/Toolbar';

function Header() {
  const [viewMode, setViewMode] = useState<ViewMode>('grid');
  return <Toolbar viewMode={viewMode} onViewModeChange={setViewMode} />;
}
```
