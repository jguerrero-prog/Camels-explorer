# ChartModeDropdown

Real fix (2026-08-06, direct user feedback: "the static/interactive toggle is becoming illegible at times... I think it's because it sits inside the plot" + "perhaps the static/interactive toggle should be a small dropdown where users could decide between static, interactive, or table"). Replaces `PlotChart`'s old two-button segmented pill (`.plot-chart__toggle`, which floated `position: absolute` on top of the chart itself, occasionally colliding with plotted content underneath it) with a small dropdown rendered in `PlotTile`'s header row instead — always on the tile's own opaque background, never over the chart.

## Token

- `--color-surface-control` / `--color-border-subtle` — the closed trigger's own box
- `--color-surface-chrome` — the open menu's surface
- `--color-surface-toggle-active` — option hover state
- `--color-accent-gradient-start` — the selected option's checkmark

## Spec

A small trigger button (current mode + chevron) opens a portal-rendered menu listing every option in `options`, with a checkmark on the current selection — same portal/fixed-position pattern as `SelectField`'s own dropdown, scaled down for 2-3 short options instead of a long field list.

**Real fix (2026-08-07, direct user feedback: "the labels are bleeding out of the dropdown modal and the checkmark is overlapping with the text"):** the menu used to be forced to exactly the trigger's own width (`width: menuRect.width`) - fine for `SelectField`, whose trigger is always `width: 100%` of a full sidebar field, but this trigger is a small content-sized pill that only fits whichever label is *currently selected*. With "Static" selected, the trigger (and thus the menu) was too narrow for "Interactive" - a real option, not a hypothetical one - to fit on one line, so it wrapped/overflowed and collided with the checkmark. Fixed by using `min-width` instead of a hard `width`, so the menu can grow past the trigger's own width to fit its longest real option, plus `white-space: nowrap` on each option so a long label never wraps onto a second line in the first place.

**Real, deliberate constraint: `options` never contains a disabled entry.** Every option passed in is always genuinely real for this tile - "Table" only appears when `halos` exists, "Static" only when a server-rendered PNG exists. `PlotTile`'s own `availableChartModes` computes this list; this component has no opinion about *why* an option is or isn't present, only about rendering whichever list it's given.

**Single-option case, handled by the caller, not here:** if a tile only ever has exactly one real mode (e.g. 3D Density Field: Interactive only, no Static, no halos), `PlotTile` doesn't render this component at all - matching the original toggle's own "no toggle when nothing to switch to" behavior. This component itself doesn't special-case a 1-item `options` array; it would render a dropdown with one option and nothing to compare it against, which is real but pointless chrome `PlotTile` avoids by not mounting it in the first place.

**4th mode added 2026-08-07, direct user request: `'scatter3d'` / "3D Scatter"** - Black Hole Mergers wanted a 3D scatter alongside Interactive/Table, so `ChartDisplayMode` grew a 4th value rather than special-casing a single tile. `PlotTile`'s `availableChartModes` only includes it when a new `chart3d` prop is set (see `PlotTile.mdx`) - same "never a disabled/hypothetical option" constraint above applies to this one too.

## Usecase

- Rendered by `PlotTile` in its own header row, next to the tile's title - see `PlotTile.mdx`'s "Real fix (2026-08-06)" note for the full plot/table view-split this enabled.
- `PlotChart` itself no longer owns any display-mode state or toggle UI - it's now a fully controlled renderer taking `displayMode` as a required prop (see `PlotChart.mdx`).

## Code

```tsx
import { ChartModeDropdown } from '@/components/ChartModeDropdown/ChartModeDropdown';
import type { ChartDisplayMode } from '@/components/ChartModeDropdown/ChartModeDropdown';

function Example() {
  const [mode, setMode] = useState<ChartDisplayMode>('static');
  const options: ChartDisplayMode[] = ['static', 'interactive', 'table'];
  return options.length > 1 ? (
    <ChartModeDropdown mode={mode} options={options} onChange={setMode} />
  ) : null;
}
```
