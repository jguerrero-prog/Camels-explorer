# Filter settings

Chooses which catalog fields act as filters on a custom plot. A full-size modal, because a field tree does
not fit in a sidebar column.

`Source: figma:1066:10`

## Anatomy

```
.filter-settings-modal-backdrop       portal to document.body, click to dismiss
└── .filter-settings-modal            role="dialog", aria-modal, aria-label="Filter settings"
    ├── __header                      __title + __close
    ├── __divider
    └── __body                        caption, then CustomFilterTree
```

Four of the five stories are states rather than content, because the tree is fetched and scoped:

- **No type selected** — the tree is filtered by the object type, so with no type there is nothing to show.
  The body says "Pick a Type first" rather than rendering an empty tree.
- **Loading** and **Error** — as elsewhere in the custom flow, the error names the likely cause rather than
  reporting a failure abstractly.
- **Fields already added** — groups holding active fields show a count badge, so a long tree still shows
  where the current selection sits.

## Behaviour

- Rendered through a portal to `document.body`, so it is never clipped by the sidebar or the tile it was
  opened from.
- Opened from two places with the same content: at tile creation, from the Add Plot modal's narrow column,
  and afterwards from the custom sidebar. One full-size home replaced two cramped ones.
- Nothing is pre-selected. Filters are opt-in, so a new custom plot starts unfiltered.
- The tree is scoped to the selected object type; fields from other types are not shown.

## Accessibility

The most complete overlay in the application, and the model the others should follow:

- `role="dialog"` with `aria-modal="true"` and an `aria-label`.
- Escape closes it, via a document-level key listener cleaned up on unmount.
- The backdrop dismisses only on a direct hit, so a drag that ends on the backdrop does not close it.
- The close button carries both `aria-label` and `title`.
- `Source: gap`. Focus is neither moved into the modal on open nor trapped inside it, and is not restored to
  the trigger on close.

## Content

- The caption states the rule: "Add fields as live filters. Nothing is pre-selected."
- Field and group names are catalog names, unchanged. Descriptions and units are shown as published.

## Use it

- Choosing filter fields for a custom plot, from either entry point.

## Don't use it

- To set filter values. The chosen fields get range controls in the sidebar.
- For the curated statistics, which are selected by simulation rather than filtered.
