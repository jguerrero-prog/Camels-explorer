# StaticImageChart

A server-rendered plot image, with an inline error state when it cannot load.

`Source: code`

## Anatomy

```
.plot-chart                  borrowed from PlotChart, the white card
├── .plot-chart__image       the server-rendered PNG
└── .plot-chart__error       replaces the image when it fails to load
```

The simplest chart path: the backend draws the plot with matplotlib and returns a PNG, and this shows it.
It has no stylesheet of its own and imports `PlotChart.css`, so the image sits on the same white card as
every other chart. 17 of the 19 statistics have a `plot.png` endpoint; the two 3D statistics do not.

## Variants and states

<Canvas of={Stories.BrokenImage} />

The error state is reached whenever the image fails, which in practice means the backend is not running. It
names the command that fixes it rather than reporting a status code.

## Tokens

None of its own. The card comes from `PlotChart`.

## Behaviour

- `imageUrl` is a `plot.png` endpoint with the statistic's parameters as query string.
- The image is sized to the tile, not the other way round.
- A failed load swaps the image for the error state rather than leaving a broken-image icon.

## Accessibility

- `alt` is required by the type, which is more than `PlotChart` does.
- `Source: gap`. Callers pass a generic alt. A useful one would name the statistic, the suite and the
  realization, since that is what distinguishes one plot image from another.

## Content

The error names the likely cause and gives the command that fixes it, rather than reporting a failure
abstractly: "Couldn't load the chart image, is the API server running?" followed by the `uvicorn` line. The
`alt` text is the caller's and should describe the plot, not say "chart".


## Use it

- A statistic whose server renderer exists and whose data does not need interaction.

## Don't use it

- When the reader needs to zoom or hover. Use `PlotChart` in interactive mode.
