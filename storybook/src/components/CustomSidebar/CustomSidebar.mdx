# CustomSidebar

The Custom tile's real per-tile sidebar (added 2026-08-05) - reuses `CustomFieldsForm`, the exact same field-picking UI the Add Plot modal's Custom tab uses, so a Custom tile's filters/fields/chart type stay editable after creation, the same real capability every other statistic's own per-tile sidebar already has.

## Token

Composes `ParamsSidebar`'s own shell/scroll/fade (see `ParamsSidebar.mdx`) - no tokens of its own beyond what `CustomFieldsForm`/`CustomFilterValues`/`CustomFilterSettings` already use.

**This story fetches real, live data** - `api.ts`'s `API_BASE` points directly at `localhost:8010`, not relative to whatever port Storybook itself runs on, so this renders exactly like the real app when the FastAPI backend (`uvicorn api.main:app --port 8010`) is running locally. With it stopped, this shows the real "Couldn't load real field metadata — is the API server running?" error path - both are genuine states, neither is a Storybook-only mock.

Real fix (2026-08-05, direct user feedback): this used to render `CustomFieldsForm` with its full inline Filters tree (every field, always expanded) ahead of the actual values - "looks like an exact copy and paste" of the Add Plot modal. Now: top-level choices (`showFilterTree={false}`) → live values for whichever fields are already active (`CustomFilterValues`) → a divider → a collapsed-by-default "Filter settings" section (`CustomFilterSettings`) holding the same tree.

Real fix (2026-08-06): its own scroll/fade overflow handling (base pickers + N filter values + the tree, filters unbounded in count) used to be hand-rolled entirely in this component. Generalized into `ParamsSidebar` itself instead, so every sidebar shares the same real scroll-then-fade affordance.

## Usecase

- Rendered by `App.tsx` whenever the focused tile's `kind === 'custom'`, in the same left-sidebar slot every other statistic's own sidebar occupies.
- `onChange` flows into `App.tsx`'s `refetchCustomTile`, which turns an edited selection into a real, live re-fetch of the already-rendered tile next to it - dragging a filter range here gives immediate visual feedback a value picked blind inside the modal never could.

## Code

```tsx
import { CustomSidebar } from '@/components/CustomSidebar/CustomSidebar';

<CustomSidebar
  selection={tile.selection}
  onChange={(selection) => refetchCustomTile(tile.id, selection)}
  onRemove={() => removeTile(tile.id)}
/>
```
