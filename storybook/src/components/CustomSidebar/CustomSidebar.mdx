# Custom plot

The sidebar for a custom tile. Unlike the curated statistics, it selects rows by filtering the catalog
rather than by naming a simulation.

`Source: code`

## Anatomy

```
ParamsSidebar title="Custom", footer = Remove plot
├── CustomFieldsForm       x field, y field, colour field, aggregation
├── CustomFilterValues     one range control per active filter field
└── CustomFilterSettings   opens Patterns / Filter settings to choose which fields filter
```

## Variants and states

The field list is fetched, so the sidebar has three states rather than one:

- **Loading** — a single line while the field list is in flight.
- **Error** — "Couldn't load field metadata" plus a prompt to check the API server, because this failure is
  almost always a local one that the reader can fix.
- **Ready** — the three sections above.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-text-muted` | The loading line |
| `--color-danger` | The error line |

The shell, its scroll behaviour and its pinned footer belong to `ParamsSidebar`.

## Behaviour

- Two requests populate the sidebar: the flat field list for the pickers, and the field tree for the filter
  chooser.
- Filters are chosen in a modal, not inline. A filter set can be long, and an unbounded collapsible section
  inside a scrolling sidebar was not navigable.
- The scroll-and-fade treatment comes from `ParamsSidebar`, which every sidebar shares.

## Accessibility

Inherited from `ParamsSidebar` and the composed fields.

- `Source: gap`. The loading and error lines are plain paragraphs with no live region, so a change of state
  is not announced.

## Content

Field names are catalog names, unchanged, so that a selection here matches what a user would write in a
query. Units come from the catalog where published.

## Use it

- For any question the curated statistics do not answer directly.

## Don't use it

- For a published statistic. The curated sidebars are faster and their output is precomputed.
