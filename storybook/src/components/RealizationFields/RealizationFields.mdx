# Realization fields

The opening block of every statistic sidebar: which simulation you are looking at, before any
statistic-specific setting. Renders no markup of its own, only other fields.

`Source: code`

## Anatomy

The block is conditional, not a fixed list. What renders depends on the set:

```
Suite            SelectField        hidden when comparing by suite
Set              SelectField        LH · CV · 1P · EX · BE · SB
Compare mode     Checkbox           hidden for 1P
  1P             SelectField "1P Parameter" + OptionSlider "Variation"
  compare off    NumberStepper "Realization"
  by realization MultiSelect "Realizations to compare"
  by suite       NumberStepper "Realization" + MultiSelect "Suites to compare"
```

## Variants and states

The set drives everything below it, and three cases are worth knowing:

- **1P** replaces the realization stepper with a parameter picker and a variation slider, because a 1P run
  is identified by which parameter was varied and by how much, not by an index. Compare mode is forced off
  here: a 1P identifier is compound, and the compare control only carries numbers.
- **SB** is published for IllustrisTNG and Astrid only. For any other suite the block shows a caption
  saying so, instead of a stepper with no valid range.
- **Comparing by suite** hides the Suite picker, because the suite is now the axis rather than a fixed
  choice, and seeds the compare list with whatever suite was selected so the list is never empty.

## Tokens

None directly. Every visible surface belongs to the fields this block composes.

## Behaviour

- Changing the set resets the realization, since an index valid in one set may not exist in another.
- When a statistic offers a narrower range of suites or sets than the catalog, the block snaps to the first
  allowed option rather than leaving an invalid selection in place.
- Realization ranges and 1P parameter lists come from `GET /api/metadata`, so they match the published data
  rather than a hard-coded list.
- Where a 1P parameter has no published variation at a given step, the caption says so and asks for another
  step, because that is a gap in the public release and not an error.

## Accessibility

Inherited from the composed fields. This block adds no controls of its own.

## Content

- The set is shown by its label, not its code.
- 1P parameters are named for IllustrisTNG, where the names are published, and numbered `p1`, `p2` for
  other suites where they are not.
- Captions state ranges as `0–999` and counts as "1,000 realizations available".

## Use it

- At the top of any per-tile sidebar for a curated statistic.

## Don't use it

- Where only one simulation can be selected. Use `Realization fields (single)`.
- In the custom flow, which selects by filter rather than by realization.
