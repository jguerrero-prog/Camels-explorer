# RealizationFields

The Suite / Set / Compare mode / Realization(s) block every per-tile sidebar in this app opens with. Extracted 2026-08-05 from `MassRangeSidebar` when `PowerSpectrumSidebar`, `BispectrumSidebar`, and `SFRHistorySidebar` were all about to duplicate the identical block — real duplication crossing this project's own "three strikes" line, not a pre-emptive abstraction.

## Token

Inherits everything from its composed fields — see `SelectField.mdx`, `Checkbox.mdx`, `MultiSelect.mdx`, `NumberStepper.mdx`. No tokens of its own.

## Spec

<Canvas of={RealizationFieldsStories.Playground} />
<Controls />

- Suite / Set: `SelectField`, options from `GET /api/metadata` (via `useCatalogMetadata`, the extracted fetch hook every statistic sidebar now shares).
- Compare mode: `Checkbox`. Off → `NumberStepper` "Realization". On → `MultiSelect` "Realizations to compare".
- Changing Set resets `realizations` to `[0]` — a different set has a different, unrelated realization count, so keeping a stale index risks silently picking an out-of-range realization for the new set.

**Real bug fixed 2026-08-05: SB (Sobol sequence) was completely absent from the Set dropdown.** Found during a full param-wiring audit against `app.py` (which has always offered it), prompted by direct user report. `backend.py` already fetches SB data correctly for any statistic whose real files use it (Power Spectrum, FOF/Subfind → HMF/SMF/Baryon Fraction/Galaxy Scaling Relations, Rockstar, SubLink, the raw SFR history file) — the gap was purely that no UI path could select it. Two real complications SB has that no other set does, both handled here:
- **Its real per-suite folder name differs** (IllustrisTNG → `SB28`, Astrid → `SB7`, confirmed via real directory listings) — resolved server-side now (`api/deps.py`'s `resolved_set_name` FastAPI dependency, applied to every router endpoint's `set_name` param via `Annotated[str, Depends(...)]`), mirroring `app.py`'s own `set_name = sb_folder or "SB"` right after its Set selectbox. The frontend just sends the literal string `"SB"`, same as any other set.
- **Its realization count is per-suite, not one flat number** — `CatalogSet.realizations` is `null` for the SB entry; the real bound comes from `GET /api/metadata`'s new `sb_realizations_for_suite` map instead, via the shared `realizationCountFor(catalog, setName, suite)` helper. SIMBA/Swift-EAGLE have no real SB set at all (missing from that map) — picking SB with either shows an honest warning caption rather than a fabricated realization bound, matching `app.py`'s own real "⚠️ SB isn't published for {suite}" caption.

**Real bug fixed 2026-08-05: 1P (One-Parameter-at-a-time) was selectable in the Set dropdown but non-functional** — its real public folders are compound-named by parameter+variation (e.g. `1P_p11_2`), not `1P_{realization}` like every other set, so the plain `NumberStepper` this component always rendered could never produce a realization that resolved to real data. `realizations` widened from `number[]` to `(number | string)[]` to hold the compound id; `RealizationFieldsValue` itself is otherwise unchanged (still just "a realization," per set). Mirrors `app.py`'s own `onep_supported` branch:
- **Compare mode is hidden entirely for 1P** (the `Checkbox` and the `MultiSelect`/`NumberStepper` pair below it) — matches `app.py`'s own `compare_mode = False; compare_realizations = [realization]` for this set. A compound id can't be represented in the number-only "Realizations to compare" `MultiSelect`.
- **"1P Parameter" `SelectField` + "Variation" `OptionSlider`** (options `[-2, -1, 0, 1, 2]`, 0 = fiducial) replace the `NumberStepper`. IllustrisTNG gets real named parameters (`onep_tng_params` from `GET /api/metadata`, e.g. "p1: Omega_m (cosmological)") — every other suite gets generic "p{N}" labels (`onep_max_index_for_suite`), since most of their parameters aren't exposed in their own output-file metadata either (a real data limitation, not a missing feature — see `backend.py`).
- **Missing-variation warning** (`onep_tng_missing_variations`, e.g. p15 has no real `-2`/`-1` simulation) and a **real-value caption** (`GET /api/onep-param-value`, IllustrisTNG only — other suites' parameters aren't directly readable this way) — both live fetches via new `useCatalogMetadata.ts` helpers (`parseOnepRealizationId`, `useOnepParamValue`).
- Server-side, only the 6 real statistics `app.py` itself covers for 1P (Power Spectrum, HMF/SMF/Baryon Fraction, Galaxy Scaling Relations, Color-Mass Diagram) had their `realization`/`realizations` API params widened from `int` to `str`/`list[str]` — deliberately **not** every endpoint. Statistics 1P doesn't cover (Bispectrum, SFR History here; six more behind `SingleRealizationFields`) keep `realization: int` server-side, so picking 1P there fails with a clean 422 rather than corrupting a byte-offset calculation in the CMD-grid-backed paths (`_fetch_npy_stack_slice` reads a realization index as an actual array offset — passing it a string there, not just an unresolved one, was the real risk this scoping avoids).
- **Known gap, not fixed here**: the "Add Plot" modal's `CuratedTab` has its own separate, simpler Suite/Set/Realization picker (a plain `NumberStepper` regardless of Set) that predates both the SB and 1P fixes above — selecting 1P there before a tile exists still can't produce a valid realization. Once the tile is created, this component's own Set field (used by every per-tile sidebar) is unaffected and works correctly.

## Usecase

- Real usage: the first four fields inside `MassRangeSidebar`, `PowerSpectrumSidebar`, `BispectrumSidebar`, `SFRHistorySidebar` — every one of them renders this, then appends its own statistic-specific fields (mass range, Power Spectrum's grid/MAS/ptype/k-range, Bispectrum's field/triangle-shape, SFR History's z-range/symbolic-fit) below it.
- Not every statistic uses this — several (Galaxy Scaling Relations, 3D Density Field, 3D Particle Cloud, 2D Field Map, Halo Gas Profiles, Color-Mass Diagram, Lyman-alpha Spectrum) are real, single-realization-only views per `app.py`'s own `SINGLE_REALIZATION_STATISTICS` tuple — their sidebars use a plain `NumberStepper` "Realization" with no Compare mode `Checkbox` at all, not this component.

## Code

```tsx
import { useState } from 'react';
import { RealizationFields } from '@/components/RealizationFields/RealizationFields';
import type { RealizationFieldsValue } from '@/components/RealizationFields/RealizationFields';
import { useCatalogMetadata } from '@/lib/useCatalogMetadata';

function Sidebar() {
  const catalog = useCatalogMetadata();
  const [value, setValue] = useState<RealizationFieldsValue>({
    suite: 'IllustrisTNG', setName: 'LH', compareMode: false, realizations: [42],
  });
  return <RealizationFields catalog={catalog} value={value} onChange={setValue} />;
}
```
