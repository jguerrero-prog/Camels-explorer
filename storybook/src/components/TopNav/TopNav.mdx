# TopNav

The 48px bar across the top. Holds the toolbar on the left and Add Plot on the right.

`Source: figma:1113:1583`

## Anatomy

```
.top-nav                48px + 1px bottom border, surface/chrome, padding 0 28
├── toolbar             optional slot, left
├── loadingIndicator    optional slot
└── .top-nav__add-plot  32px, radius 9, add-plot/surface, margin-left auto
```

Add Plot is pinned right with `margin-left: auto` rather than `space-between`, because the toolbar is
conditional: with `space-between` and no toolbar, the button would jump to the left edge.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-surface-chrome` | Bar fill |
| `--color-border` | Bottom border |
| `--color-add-plot-surface` / `--color-add-plot-text` | The Add Plot button, the one inverted control |
| `--font-label` | Button label |

## Behaviour

- Fixed 48px content height plus a 1px border, so the canvas below never shifts.
- The Add Plot button is 32px and matches `LoadingIndicator`, so swapping them does not change the bar.
- The bar holds no title or breadcrumb. Context lives on the tile.

## Accessibility

- `Source: gap`. No `role="banner"` and no landmark, so the bar is not reachable as a region.
- The Add Plot button is inline markup rather than the `Button` component, so its focus and disabled
  behaviour are defined twice. Consolidating them would fix both at once.

## Content

One button, named for the outcome: "Add Plot".

## Use it

- Once, as the app's top bar.

## Don't use it

- For per-tile actions. Those belong on the tile or in the toolbar.
