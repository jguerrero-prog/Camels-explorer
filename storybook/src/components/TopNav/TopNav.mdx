# TopNav

The 48px header row — the folder/project name on the left, the primary "Add Plot" action on the right, and (once a plot exists) `Toolbar` in the same row, between the two. Sourced from two real frames: the zero-plots "Skeleton" (Figma node `1113:1583`, no toolbar) and the Stellar Mass Function drill-down's real `header` (node `1012:1124`, toolbar present).

## Token

- `--color-surface-chrome` — background (shared with IconRail — both are "chrome", not content)
- `--color-border` — bottom border
- `--font-ui` (Inter) — folder/project text
- `--font-label` (Lato), weight 600 — "Add Plot" button label (see the deviation note below: the raw Figma frame specifies 700)
- `--color-text-muted` / `--color-text-faint` / `--color-text-emphasis` — the three text weights (folder / separator / project)
- `--color-add-plot-surface` / `--color-add-plot-text` — the Add Plot button's own light-surface/dark-text pair (see below)

**Real fix (2026-08-06, direct user feedback):** the button's fill flipped from the diagonal purple→red accent gradient to a solid light surface (`--color-add-plot-surface`, white) with dark text/icon (`--color-add-plot-text`, reusing `--neutral-900` — the same literal `PlotChart.tsx` already hardcodes for dark-text-on-white) — the one deliberately inverted control in this app's otherwise all-dark chrome.

**Deliberate deviation from Figma (2026-08-04):** the raw frame specifies the label at `font-weight: 700` (Lato Bold); implemented at `600` per direct user request after seeing it rendered — one weight lighter than the literal spec. Noted here rather than silently matching Figma's stated value, since this is a real, intentional adjustment, not an oversight.

**Confirmed 2026-08-04, correcting an earlier misreading:** this is **not** a breadcrumb navigation trail — it's the folder name and the project name, two independent pieces of identity, not a clickable hierarchy to navigate up through. Renamed props/classes accordingly (`folderName`/`projectName`, `.top-nav__path*`) so the code doesn't imply breadcrumb semantics that aren't real.

**Still open:**

## Usecase

- One `TopNav` per app shell, always visible — this is chrome, not a per-tile control.
- `onAddPlot` here is specifically **"add a new empty tile to the canvas."** `STUDIO_PLAN.md`'s "Adding tiles" section already settled that this stays a single, low-ceremony action, not a wizard.

**Corrected 2026-08-04:** this is a distinct action from `Tile`'s own per-tile `onAddPlot` (opening a statistic picker for *that* tile, not built yet) — they were wrongly wired to the same handler in the first real app build, which meant clicking any existing empty tile added a whole new sibling tile instead of doing nothing. See `Tile.mdx` Usecase.

**Real gap (also confirmed 2026-08-04):** no design exists yet for what happens once the canvas already has one or more tiles and this button is clicked again — does it add a blank tile immediately, or open a picker first? Only the very-first-tile case is designed (the "Skeleton" frame). Currently implemented as "always add a blank tile," the simplest reading, not a confirmed final answer.
