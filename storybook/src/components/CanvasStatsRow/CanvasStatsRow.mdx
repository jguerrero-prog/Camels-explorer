# CanvasStatsRow

The four pill-shaped stat chips ("1,000 LH Realizations", "4 suites", "15 Statistics", "5 Halo finders") from the "Skeleton" frame (Figma node `1113:1583`). Originally built as part of `Tile`; **extracted out on 2026-08-04** once the real behavior was confirmed — see Usecase.

## Token

- `--color-surface-sunken` (pure black) — chip background, distinct from the tile's own surface
- `--color-border` — chip border
- `--font-label` (Lato) — both the bold value and the muted label
- `--color-text-primary` / `--color-text-muted` — value vs. label weight

- A row of pill chips (`border-radius: 999px`), evenly split (`flex: 1 0 0` each), each holding a bold value + muted label.

## Usecase

**Confirmed 2026-08-04, correcting the original assumption this was per-tile:** this row shows **only when the whole canvas has zero plots** — the very first moment, before anything has been added anywhere. It is not repeated per empty tile, and it disappears entirely once *any* plot exists on the canvas, regardless of which tile it was added to.

The values are confirmed to be **live, not static** once wired — they update in response to real app/data state even while the canvas is still in this empty moment (e.g. if a future control changes scope before any plot is added). The current `stats` prop already supports that; only the actual data source is still missing.

**Placement, re-corrected 2026-08-04 against real Figma evidence (node `1113:1609`):** this renders as the *last child inside the same card* as the canvas's lone starter `Tile` — passed via `Tile`'s `footer` prop — not as a separate row floating above the tile grid. An earlier app build placed it above `Viewer` as an independent sibling; a direct `get_design_context` pull showed the real "stats-row" node nested inside "Panel 1" itself, after its empty-state block. The *ownership* rule from the original correction still holds — `Tile` doesn't decide whether to show this, the canvas-level caller does — only the rendering position changed. See `Tile.mdx`'s Usecase and Code.
