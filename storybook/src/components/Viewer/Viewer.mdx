# Viewer

The canvas that holds the tiles, in either a two-column grid or a single stacked column.

`Source: figma:1019:112`

## Anatomy

```
.viewer                 8px padding, 8px gaps, overflow-y auto, surface/canvas
├── .viewer--grid         2 columns, rows minmax(480px, 1fr)
└── .viewer--stacked      one column, each child min-height 480, flex-shrink 0
```

Grid mode has two special cases, both driven by tile count rather than by a prop:

| Tiles | Layout |
| --- | --- |
| 1 | Spans both columns, full width |
| 2 | Side by side, 544px each |
| 3 | Two on the first row, the third spans both columns |
| 4 | Two by two |

The three-tile case also switches the second row to `auto` height and lets that tile overflow visibly, so
the spanning tile sizes to its content instead of scrolling inside a row track sized for the two above it.

## Tokens

| Token | Applies to |
| --- | --- |
| `--color-surface-canvas` | The canvas, distinct from the tiles on it. See Decision log, DR-007. |

## Behaviour

- 8px padding and 8px gaps, so tiles sit tight to the canvas edge.
- Grid rows are `minmax(480px, 1fr)`: a tile never gets shorter than 480px, and grows to fill.
- Stacked tiles keep their full height and the canvas scrolls, which is why a stacked tile shows its readout
  on the right while a grid tile shows it underneath.

## Accessibility

- `Source: gap`. No `role="main"` landmark and no accessible name, so the primary content region is not
  reachable as one. Tile order follows DOM order, which is correct.

## Content

The viewer supplies no copy of its own. What a reader sees comes from the tiles it lays out, so a layout
change never rewords anything.

## Use it

- Once, as the app's content region.

## Don't use it

- For a single fixed panel. It exists to arrange a variable number of tiles.
